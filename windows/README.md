# tokcat for Windows (preview)

[简体中文](README.zh-CN.md)

Double-click `Tokcat.cmd` on Windows 10 or 11. Windows PowerShell 5.1 and Windows Forms are included with Windows; no API key is needed. Task dots and two lines of metrics are embedded as a native child window inside the primary horizontal taskbar, in free space near the notification area. The detail window starts hidden. Click the taskbar widget to open details; right-click it to hide it or quit. The detail window's **任务栏** button also toggles visibility. Launching the application again opens the existing detail window.

Taskbar button bounds are observed in the background to choose free space, without resizing Explorer's button containers. If space is insufficient, layout cannot be read, or the taskbar is vertical, the widget hides and details report the reason. There is no floating-window fallback. The widget retries attachment after Explorer recreates the taskbar and hides with the taskbar. Layout supports scaling and negative coordinates; only the primary taskbar is targeted. Visibility is saved in `%LOCALAPPDATA%\Tokcat\taskbar.json`, independently of the previous floating-strip preference.

On an interactive desktop, run `powershell.exe -NoProfile -STA -File .\windows\Test-Taskbar.ps1 -RealTaskbar` to verify the real Explorer parent, taskbar bounds and button avoidance. Ordinary package tests use an isolated host to test embedding, hiding, clicking and host recreation.

GPU utilization appears in the monitor and status strip. It is the busiest engine across GPUs, sampled in the background from Windows performance counters. A dash means the counters are unavailable or still loading.

The usage window also has a separate **CC Switch 代理** view of `%USERPROFILE%\.cc-switch\cc-switch.db`. It groups proxy requests by application, model and provider, excludes imported records, and reads at most the latest 100,000 requests in the selected period. Proxy requests can overlap with agent logs, so the views must not be added together. Costs greater than zero are those recorded by the proxy, not an actual bill; zero or invalid costs are shown as unpriced. Usage outside the proxy is not included in that view.

The taskbar window icon and notification-area icon also show the current task dots. Closing the main window keeps the application running. Windows may initially hide the notification-area icon in the overflow area; enable it in taskbar settings to keep it visible.

The preview reads Codex CLI/Desktop rollout JSONL under `%CODEX_HOME%\sessions`, or `%USERPROFILE%\.codex\sessions` when `CODEX_HOME` is unset, and the corresponding `session_index.jsonl`. It also reads the local Codex Work catalog in `sqlite\codex-dev.db`, WorkBuddy and WorkBuddy AI databases under `%USERPROFILE%\.workbuddy` and `%USERPROFILE%\.workbuddy-ai`, and DeepSeek Harness session projections under `%DSH_HOME%` or `%USERPROFILE%\.dsh`, and common Desktop directories under `%APPDATA%`. OpenClaw trajectory logs in `%USERPROFILE%\.openclaw\agents` and Kimi wire logs in `%USERPROFILE%\.kimi-work`, `%USERPROFILE%\.kimi-webbridge`, or the `kimi-desktop` and `kimi` folders under `%APPDATA%` are read as recent activity only; they cannot establish a running, waiting or completed state. The monitor reads source records locally and does not modify them. The list includes sessions updated in the last seven days, task state, title, project, phase, model, output tokens when reported, and latest activity. Double-click a Codex, Claude Code, WorkBuddy or DeepSeek row to read available user/assistant text locally. System messages, reasoning, tool output and image data are excluded; conversation text stays in memory. Claude and WorkBuddy logs are located by session ID and may be unavailable. Double-click a Work row to open its conversation or an activity-only row to open the raw record; the context menu can also open raw records. Yellow means running, orange means waiting or no activity for two minutes, red means failure, and green means a completed turn. Silence does not imply failure. The notification-area icon shows up to six task dots; hover to see counts, including when more than six are active. Completion and failure dots observed while tokcat runs remain until you right-click the corresponding task and mark it read. Unread reminder IDs and revisions are stored in `%LOCALAPPDATA%\Tokcat\reminders.json` and restored after restart when the same state is still present; entries older than seven days expire. Earlier completed tasks remain in the window without generating a new reminder. Windows notifications for waiting, completion and failure are off by default and can be enabled from the tray menu. They may contain task titles and are subject to Windows notification and focus settings.

This is an independent Windows preview, not feature parity with the macOS application. It currently supports local Codex rollout events, the local Work catalog, WorkBuddy session databases, DeepSeek Harness projections, and optional Claude Code hooks. CPU utilization, physical memory usage, network rates and locally reported Codex quota are shown in the window and notification-area tooltip. Network rates sum active non-loopback adapters; virtual adapters may count traffic more than once. Quota uses the most recent valid event found in the last 512 KiB of up to 20 recent files in each of the `sessions` and `archived_sessions` folders; its record time is displayed. A short window (up to 48 hours) is labeled `5h`, and a longer one `周`; after the recorded reset time it becomes unavailable until a new event arrives. These are client-written observations, not a live account query. Other integrations and the desktop companion are not implemented. For task state, the monitor first reads the last 512 KiB of a Codex rollout; if that has no lifecycle event, it streams the full log, skipping individual records over 2 MiB. Logs, catalog, and projections do not always expose approvals or other lifecycle signals; missing information is not inferred. Work status comes from a client-maintained catalog that can lag and does not include output tokens. WorkBuddy and Claude status are session-level and do not supply output tokens. The token count is the most recent reported count and may be per-turn or cumulative depending on the log format. Output tok/s is a rolling estimate from observed output-counter changes (approximately 60 seconds), excludes input and cache, starts after two samples and may reflect batched updates. It is unavailable after a turn finishes. The monitor makes no network requests and uses no credentials.

## Local usage and reference estimates

The Agent log view also reads OpenClaw `model.completed` and Kimi `usage.record` events, using the last-call usage for OpenClaw where available. A valid timestamp is required; missing token categories count as zero. Copies of an event in different files may be counted more than once when no reliable identifier is available; the same file path is read only once. These activity logs still cannot establish task lifecycle states.

WorkBuddy and WorkBuddy AI usage comes from generation spans in their respective `traces` directories. Cached tokens are separated from input; repeated span IDs in one file are counted once. A valid span timestamp is required, and trace files larger than 4 MiB are skipped and counted in the window. Copies across different files may be counted twice, and an unlabelled relay may make reference prices unsuitable.

DeepSeek Harness usage is observed as changes in cumulative session projections when all four input, output, cache-read and cache-write counters are present. First sight establishes a baseline; subsequent deltas observed while tokcat runs are written to `%LOCALAPPDATA%\Tokcat\dsh-usage.jsonl`, without session IDs or conversation content. Usage while tokcat is closed is not backfilled, and restarts and counter resets establish new baselines. If the model or provider changes between samples, the delta remains unattributed and unpriced. Users may delete this local journal if they no longer need the history.

The **用量统计** button reads Codex's local `sessions` and `archived_sessions`, and Claude Code's local project logs, in the background for today, seven days or 30 days. It groups input, cache-read, cache-write and output tokens by day, source, model and provider. Codex cumulative counters are differenced and duplicate observations are removed. The first cumulative sample is only included when it can be identified as the first request; a counter reset establishes a new baseline. Claude streaming records sharing a message ID are merged using the largest observed value for each counter and attributed to the latest record's date; without a message ID, deduplication uses the record ID when available. Incomplete logs, unreported token categories and records larger than 2 MiB can therefore undercount. No conversation text is saved or transmitted.

Amounts are estimates in USD, **not actual bills or subscription charges**. Default rates come from this project's bundled `UsagePricing.json` reference catalog and may be outdated. Use **编辑参考单价** to create or edit `%LOCALAPPDATA%\Tokcat\usage-pricing.json`, save it and refresh. This personal copy persists across upgrades. The `input`, `cache_read`, `cache_write`, and `output` fields are USD per million tokens; an optional `provider` scopes an entry. Tokens with no matching rate or cache-write rate are shown separately as unpriced. Official rates are not assigned to known non-official providers; unlabelled providers use official rates. Claude logs often omit relay attribution, so those estimates may use an unsuitable rate. The agent log view does not include CC Switch.

## Optional Claude Code monitoring

Run the following command to add tokcat's hooks to `%USERPROFILE%\.claude\settings.json`, then restart existing Claude Code sessions:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Configure-ClaudeHooks.ps1
```

The setup retains unrelated settings and hooks and writes a timestamped backup alongside the settings file. It uses Claude Code's [command-hook `args` format and `onFailure` option](https://code.claude.com/docs/en/hooks); use Claude Code 2.1.295 or later. Hooks record only session ID, project path, state, phase and timestamps in `%LOCALAPPDATA%\Tokcat\claude`; prompts, responses and tool inputs are not saved. Synchronous hooks may add startup latency per event. If you move the tokcat folder, remove the old hooks before moving and install again at the new location. To remove hooks installed from the current folder, run the same command with `-Remove`; this preserves other hooks and leaves prior state files intact.

Launch with an alternate data directory:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\windows\Tokcat.ps1 -CodexHome 'C:\path\to\.codex'
```

Run parser checks with `powershell.exe -NoProfile -File .\windows\Test-Monitor.ps1`.

Build a redistributable ZIP with `powershell.exe -NoProfile -File .\windows\Package.ps1`. It creates a new archive under `dist/`; extract it and run `tokcat-windows\Tokcat.cmd`. Windows CI publishes the ZIP as a workflow artifact.
